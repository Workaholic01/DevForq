# Refresh Project Knowledge

Read the existing onboarding report and project-knowledge files.

Determine what has changed since the onboarding source commit.

Focus on:

- manifests and lock files
- build and test configuration
- applications and packages
- module boundaries
- database and API contracts
- CI/CD
- infrastructure
- dependencies
- generated stack skills

Update only affected knowledge files and stack skills.

Do not replace accurate project knowledge merely to rewrite wording.

Update the onboarding report with:

- refresh date
- source commit
- files inspected
- knowledge files changed
- stack skills changed
- unresolved warnings

Do not modify production source code.
