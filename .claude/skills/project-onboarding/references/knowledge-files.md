# Project Knowledge Contracts

## PROJECT_PROFILE.md

Include product purpose, repository type, deployable units, critical constraints,
onboarding date and source commit.

## TECHNOLOGY_STACK.md

Use a table containing area, technology, version and repository evidence.

## ARCHITECTURE.md

Include architectural style, entry points, components, module boundaries,
dependency direction, request flow, data flow, authentication, asynchronous
processing and important constraints.

## REPOSITORY_MAP.md

Map important paths to responsibilities, entry points and tests.

## COMMANDS.md

For each command record:

- command
- working directory
- purpose
- source or evidence
- prerequisites
- whether it was executed

## CONVENTIONS.md

Include naming, module placement, validation, error handling, logging,
configuration, persistence and API conventions.

## TESTING_STRATEGY.md

Include frameworks, test locations, fixture patterns, test commands and coverage
expectations.

## INTEGRATIONS.md

Include external APIs, messaging systems, storage, authentication services and
observability systems. Do not include secrets.

## ONBOARDING_REPORT.md

Summarise completed discovery, warnings, assumptions and the repository commit
used during onboarding.
