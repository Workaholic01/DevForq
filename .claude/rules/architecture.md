# Architecture Rules

- Preserve existing module and service boundaries.
- Inspect similar implementations before designing new components.
- Follow the repository's established dependency direction.
- Prefer existing abstractions over new abstractions.
- Do not introduce a new architectural pattern for one isolated use case.
- Identify API, data, migration, security and deployment impact.
- Record material architecture decisions as ADRs.
- Separate required work from optional refactoring.
